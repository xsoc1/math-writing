# 配套工具的使用模式

默认最小组合：**已有 PDF 阅读工具 → 文本编辑器 → XeLaTeX / latexmk → PDF 查看器；Obsidian 使用核心 Markdown / MathJax。** 只有出现真实需求才加文献管理、图表导出或额外插件。不把工具数量当成质量。

## 1. 来源阅读模式

先搜索定位章节、定义和证明，再连续读取有关范围；同时记录印刷页、PDF页、节号和版本。有图、扫描或公式不可信时看页面，不能靠乱码自动“修复数学”。保留原书约定与原命题状态。

适配当前环境实际存在的阅读工具；不能在交付 prompt 中硬编码一个只有当前会话存在的工具名。如果文件是当前上传且已挂载，直接使用其实际路径；不编造文件路径。来源 PDF 始终只读，不把修改源书当成蒸馏步骤。

## 2. LaTeX 编写模式

**适合：** 长证明、编号、复杂图、准备打印或投稿。编辑器可用 VS Code 配合 LaTeX Workshop，其 recipe 调用 latexmk（W17）。现有项目有编译链时优先沿用。

本包推荐：XeLaTeX + CTeX（中文）+ mathtools / amsthm + unicode-math + hyperref / cleveref。需要交换图才用 tikz-cd。不要同时加载多套不相容的数学字体包。微排版可选，XeTeX 与 LuaTeX 的能力不同，不承诺 XeTeX 具备所有字形扩展功能（W18）。

仅编译自己撰写或已审阅的项目时，可使用：

```sh
latexmk -norc -xelatex -interaction=nonstopmode -halt-on-error -file-line-error -outdir=build main.tex
```

`-norc` 避免执行未知的 latexmk 配置文件；本包构建脚本还明确传递 XeLaTeX 的 `-no-shell-escape`。这不是沙箱：TeX仍能读取允许范围内的文件，不能随意编译不可信源码。不要为“方便”开启全局 shell-escape。信任并依赖项目 `.latexmkrc` 时，阅读后再决定是否去掉 `-norc`。

保存即编译适合短文；大型书稿采用按需编译或项目已有增量机制。编译成功后看日志、引用及页面，不只看退出码。`chktex` 可提示常见 TeX 用法，但可能误报，不承担数学验证。

## 3. Obsidian 笔记模式

**适合：** 可独立阅读的概念、定理、证明与主题综述，建立来源和依赖链接。先用核心功能，不用社区插件解决尚未出现的问题。

以主题笔记 / 数学单元为基本粒度。把先修、来源与“这条结果用于哪里”保留下来。稳定块链接用于跨笔记引用；标题和显示名称可修改而块 ID 尽量保持。不要在标题中放过长公式，因为检索、文件名与跨格式引用都会更难维护。

把本包 `.obsidian/snippets/math-writing.css` 合并到目标 vault，启用后测试。不要替换用户整个 `.obsidian` 目录。CSS是视觉增强，移除它不能使数学内容消失。

## 4. 文献管理模式（可选）

有较多来源时使用 Zotero 保存作者、书名、版本、章节和附件；Better BibTeX 可维持稳定 citation key 并导出 / 自动导出书目（W16）。这只是工具建议，本包没有接入或修改用户的 Zotero。

LaTeX 可使用项目要求的 BibTeX 或 biblatex / Biber；若出版社给出样式，跟随其规范。Obsidian 笔记至少保留人可读的作者—书名—章 / 节—页码，不能仅留一个别处无法解释的 citation key。本包样张用简短来源说明，未把 Biber 设置为编译必需步骤，也未宣称测试了自动文献同步。

## 5. 图表模式

交换图以 TikZ-cd 源码为准，编译后导出 SVG 或 PDF。Obsidian引用导出的图片，旁边说明关键合成关系。保留生成文件和源码的对应关系，更新图时同步两者。

依赖路线可以用 Mermaid。精确曲线、根系、几何构型应采用适合的可复现绘图工具并做数学核对；不将装饰性生成图用作证明依据。

## 6. 双格式模式

小项目维护一份明确的数学内容记录和两个输出版本即可，未必需要造转换框架。要求持续同步时先定义有限支持的语法 / AST，再显式映射定理、公式 ID、引用和图像。

Pandoc适合转换其支持的公共子集（W13）；复杂 Obsidian 文档先识别不兼容项。不要用正则把整篇任意 TeX 改成 Markdown 后宣称保持语义。任何转换都复查条件、负号、上下标、引用指向及图。

## 7. 计算与形式化模式（按需）

CAS 用来检查具体代数恒等式或发现反例；数值计算用来辅助估计与探索，均须明确条件。Lean 等工具仅在存在可执行环境和相关库时用于形式化明确命题。实际运行了哪些命题就报告哪些，不把一个局部通过标成整篇已认证，也不默认给所有写作任务加形式化工程。

## 8. 本包脚本的确切边界

`check_env.py`：查询工具路径、版本以及核心 TeX 包 / 字体，不安装软件、不改设置。它使用本机时钟记录执行时间；本次研究的访问日期另记，不混为一谈。

`build.py`：只构建本包受控的样张、骨架和交换图，禁用未知 latexmk 配置与 shell-escape；缺工具或构建失败则明确报错。输出在 `examples-output/`，日志在临时构建目录；不覆盖原书。

`lint_math.py`：检查有限的独立美元分隔符、基础数学环境配对、Markdown里的完整 LaTeX命令、重复块 ID及若干高风险语言；**不是** TeX解析器、MathJax渲染器或数学证明检查器。读到任意宏语言可能有误报 / 漏报。警告用于复查，不自动改写。

真实测试结果和未测试项见 `validation/REPORT.md`。环境检测通过不等于“所有软件都在所有平台上可用”。

`check_mathjax.cjs` 是可选的独立 MathJax 解析冒烟测试，只针对本包样张的美元分隔符子集；依赖已安装且 Node 可解析的 `mathjax-full`。其通过不等于 Obsidian 实测，也不是数学正确性认证。
